Project context

A hospital tracking its medical supplies on paper

Al-Tal National Hospital ran its medical-supply inventory — materials, receiving, department requests, deliveries — on paper. Nobody could reliably see what was running low, who asked for what, or who signed for a delivery.

HSMS is an on-premises hospital inventory platform that replaces that with a web system running entirely inside the hospital’s network: IIS and SQL Server, with no cloud services at runtime.

My role

Frontend Developer Intern at 88ninety, on a ten-person frontend team. Other engineers owned the ASP.NET Core backend and the overall architecture.

My contribution

  • The materials catalog.
  • Material create and edit flows.
  • The storekeeper dashboard.
  • Responsive hardening of the materials table.
  • Frontend integration inside the project’s permission-driven architecture.

What I built

Materials and the storekeeper’s daily view — in a fully Arabic interface

The stack is React 19 with strict TypeScript, TanStack Query for server state, Axios, React Router, and Ant Design, all inside an Arabic RTL shell.

The materials table is used daily by busy storekeepers, so it had to stay readable and usable across screen sizes — filters, actions, and long Arabic labels included.

Engineering challenge

The frontend uses permission keys rather than hard-coded role names

The system ships with several roles, but screens, menu items, and actions check a permission key, and a role is just a saved bundle of keys. I worked within that architecture, wiring my screens and actions to the right keys.

Why it matters: hard-coding roles into the frontend would turn every staffing change into a ticket for developers. With permissions resolved at runtime — in routing and menu rendering, not just by hiding buttons — the hospital’s own admins stay in control of access.

Testing and source access

The frontend suite has 85 test files written with Vitest and React Testing Library, contributed by the whole team.

It was also my first time working inside a large team with code review, shared conventions, and a deployment environment I didn’t control.
